# 構造 IO: ブロックの配置そのものを 1 つの入出力として扱う

レシピは、単体のブロックではなく**配置全体**を要求したり生成したりできます。配置は
**パターン**として 1 度だけ書き、名前でいくつのレシピからでも参照します。

パターンのファイルは `config/okmodular/structure_io/` に置きます（`recipes/` や `structures/`
と同じ階層）。ディレクトリ名は設定値です（`modular.cfg` の `structureIoDirectory`）。

> [!NOTE]
> `symbol` の入出力（[JSON フォーマット §3.2](../recipes/JSON_FORMAT.md#32-ブロックsymbol)）が
> 数えるのは**個数**です — 「その記号のどこかに 3 個」。パターンが訊いているのは別の質問で、
> 「**この形が、この向きで、このブロックのところに**あるか」です。

## 1. ファイル構造

1 ファイルに、パターン 1 個・配列・`patterns` 配列を持つオブジェクトのいずれでも書けます。

```json
{
  "patterns": [
    {
      "name": "altar_core",
      "anchor": "Q",
      "mappings": {
        "S": "minecraft:stone",
        "G": "minecraft:gold_block:0"
      },
      "layers": [
        [ "SSS",
          "SQS",
          "SSS" ],
        [ "G G",
          "   ",
          "G G" ]
      ]
    }
  ]
}
```

## 2. プロパティ

| プロパティ | 型 | 説明 |
| :--- | :--- | :--- |
| `name` | String | レシピから参照する識別子（必須・重複不可） |
| `layers` | Array | 形状。構造体定義と同じ書き方（`shape` と**排他**。どちらか必須） |
| `shape` | Object | 形を**生成**する（`layers` の代わり）。[下記](#手で描かずに形を生成する) |
| `mappings` | Object | 文字 → ブロック ID、または[セルの書き方](#セルの書き方--確率と重み)のオブジェクト。構造体定義が受ける複数候補形式は使えません |
| `anchor` | String | レシピが名指ししたブロックに重なるセルを示す 1 文字。既定は `Q` |

`layers` は行文字列の配列でも `{ "rows": [...] }` でも書けます（構造体定義と同じ 2 通り）。

形が球のように単純なら、手で描かず `shape` で生成できます（[下記](#手で描かずに形を生成する)）。

> [!WARNING]
> **どの層も行数を揃えてください。** 行の順は**層ごとにその層の行数で**反転するので、
> 行数の少ない層だけ他とずれます。省略せず、空白だけの行で埋めてください。

### 予約文字

| 記号 | 意味 |
| :--- | :--- |
| （空白） | パターンに含まれない。検査も設置もしない |
| `_` | 空気。input では「空気であること」、output では「空気にする」 |
| アンカー | `mappings` に無ければ**印だけ**で、そのセルには手を付けない |

それ以外の文字は `mappings` に**必ず**エントリが要ります。無い文字があるとファイルは
読み込まれず `structures/errors.txt` に出ます。黙って落とすと、**見た目より少ない数の
ブロックしか検査しないパターン**ができてしまうからです。

### セルの書き方 — 確率と重み

`mappings` の値はブロック ID 文字列のほか、オブジェクトでも書けます。

| キー | 何を決めるか | 既定 |
| :--- | :--- | :--- |
| `block` | そのセルに置くブロック | — |
| `weights` | **置くなら何を置くか**。ブロック ID → 重み | — |
| `chance` | **そのセルに何か置くか**（0.0〜1.0） | `1.0` |

```json
"mappings": {
  "A": "minecraft:stone",
  "B": { "block": "minecraft:stone", "chance": 0.7 },
  "C": { "weights": { "minecraft:iron_ore": 8, "minecraft:gold_ore": 2 } },
  "D": { "chance": 0.7, "weights": { "minecraft:iron_ore": 8, "minecraft:gold_ore": 2 } }
}
```

- **B** … 70% のセルに石。残りは**手を付けません**
- **C** … 全セルに置き、内訳が 8:2
- **D** … 70% のセルに置き、置いたセルの内訳が 8:2

`chance` と `weights` は**直交した別の軸**です。片方だけでも両方でも書けます。

**`block` は「1 項目だけの `weights`」の短縮形**なので、両方書くとロードエラーになります。
同じマスの中身を 2 通り指定したことになり、どちらかを黙って選ぶしかなくなるからです。

#### `weights` のキー

ブロック ID のほか、`layers` と同じ 2 つの予約文字が書けます。

| キー | 意味 |
| :--- | :--- |
| `_` | 空気（**セルを消す**） |
| `" "`（空白） | **手を付けない** |
| `modid:name:*` | ❌ **ロードエラー**。ワイルドカードは照合用で、置くブロックを指せません |

「確率で消す」と「確率で手を付けない」は別のことなので、両方書けるようにしてあります。

#### 式で書く

`chance` も重みも、数のかわりに[式](../recipes/EXPRESSION_REFERENCE.md)が書けます。

```json
"mappings": {
  "X": { "chance": "tier * 0.2", "weights": { "minecraft:iron_ore": "tier", "minecraft:gold_ore": 1 } }
}
```
→ Tier が上がるほど**濃く**なり、内訳も**鉄寄り**になる鉱脈。

**数で書いた `chance` と重みは、1 回の配置につき 1 回だけ評価されます。** Tier・充填率・天候は
どのセルでも同じ値なので、セルごとに評価しても答えは変わらず、半径 8 の球なら 2109 倍払うだけです。
**セルごとの散らばりは座標由来の抽選が担当**していて、式の仕事ではありません。

**式で書いた場合は、セルごとに評価されます。** 式は下の `cell_x` / `cell_y` / `cell_z` で
**そのセルの位置を読めるので**、配置の時点では値が決まりません。Tier しか読まない式まで
巻き込まれますが、これは意図した割り切りです（数千回の軽い評価と引き換えに、
「畳めるかどうか」の判定を 1 つに保っています）。

#### セルの位置を式から読む

| 変数 | 何を指すか | 向き |
| :--- | :--- | :--- |
| `x` / `y` / `z` | **そのセルのワールド座標** | マイクラどおり |
| `cell_x` / `cell_y` / `cell_z` | **アンカーからそのセルまでのズレ** | パターンの軸．`cell_y` は書いた層の上が正．機械の向きと一緒に回る |

横置きの機械では `y = アンカーのワールド y + cell_y` が成り立つ．縦置きの機械では成り立たない（パターンの「上」が水平を向くため）．

```json
"mappings": {
  "X": { "block": "minecraft:iron_ore",
         "chance": "1 - sqrt(cell_x^2 + cell_y^2 + cell_z^2) / 8" }
}
```
→ アンカーを中心に、**外へ行くほど薄くなる**半径 8 の塊。`X` で埋めた立方体を 1 個描くだけで、
濃淡は式が作ります。濃さごとに文字を分けて層を描き分ける必要はありません。

これで書けるようになるもの:

| 書きたいこと | 式 |
| :--- | :--- |
| 輪郭をぼかす | `"chance": "1 - sqrt(cell_x^2 + cell_y^2 + cell_z^2) / 8"` |
| アンカーより上ほど薄い | `"chance": "1 - cell_y * 0.2"`（`cell_y` は上が正） |
| 中心ほど良い鉱石 | `weights` の重みを距離で書く |
| ある深さより下だけ | `"chance": "y < 40 ? 1 : 0"` |
| 縞・市松 | `"chance": "cell_x % 2"` |

> [!NOTE]
> **`cell_*` はパターンの軸で測るので，形と一緒に機械の向きで回る．** 縦置きの機械でも，
> 書いたとおりの形と濃淡になる．北向きの横置き機械では，ワールドの軸で測った値と一致する．
> 地層のようにワールドに対して水平であってほしいものは，`cell_y` ではなくワールド座標の `y` で書く．

> [!NOTE]
> **`cell_*` はパターンの `mappings` の中でだけ意味を持ちます。** レシピの `amount` や
> `duration` に書いても 0 を返します（機械が繋がっていないときに `tier` が 0 になるのと同じ扱い）。

> [!NOTE]
> **式で書いた `chance` は、たとえ 1.0 を返す式でも「非決定」として扱われます。**
> 実際にいくつを返すかはロード時には分からないからです。`structure` 入力に使いたい
> パターンでは、`chance` を書かないか定数 `1.0` にしてください。

> [!IMPORTANT]
> **`chance` に外れたセルは「空気になる」のではなく「手を付けない」です。**
> そこにあったブロックはそのまま残ります。消したいなら `weights` に `"_"` を足してください。

> [!WARNING]
> **確率や重みを持つパターンは、`structure` 入力に使えません。** ロード時にエラーになります。
> 置くたびに違う配置になるのが目的なので、「この配置があるか」という照合が成り立たないからです。
> 実行時に静かに一致しないままだと「レシピが動かない」としか見えないので、書いた時点で断ります。

#### 散り方について

抽選は**セルのワールド座標**を混ぜるので、

- 隣り合うセルは**別々の答え**になります（全部置くか全部置かないかに潰れません）
- 同じレシピが**アンカー 2 箇所に**書いた場合、**2 箇所は別の配置**になります
- 同じ実行の中では何度聞いても同じ答えです（セーブ・ロードを跨いでも同じ）
- 次の実行では別の配置になります

#### 塊で湧かせる — `noise(scale)`

`chance` の抽選は**セルごとに独立**なので、距離で濃淡を付けても中身は均一になります。
`noise(scale)` は**近い座標で近い値を返す場**で、これを使うと塊になります。

> [!IMPORTANT]
> **`noise()` は確率として渡すのではなく、閾値で切ってください。**
>
> ```json
> "chance": "noise(8)"        ← 塊になりません
> "chance": "noise(8) > 0.5"  ← 塊になります
> ```
>
> `chance` の値がなめらかでも、**置くかどうかの判定は依然としてセルごとの独立な抽選**です。
> 場が 0.5 付近の領域では 50/50 の散らばりがそのまま出るので、
> 「密度がなめらかに変わる均一な散らばり」になります。
>
> 比較で切れば 1 か 0 しか返らないので**抽選が起きず**、場の形がそのまま出ます。
> 閾値を上げれば塊が小さくなり、下げれば大きくなります。

```json
"mappings": {
  "X": { "block": "minecraft:iron_ore",
         "chance": "noise(6) > 0.45 ? 1 - sqrt(cell_x^2 + cell_y^2 + cell_z^2) / 8 : 0" }
}
```
→ **6 ブロックほどの塊の中にだけ鉱石が出て、球の外へ行くほど薄くなる。** これが鉱脈の見た目です。
塊の中はまだ距離による抽選が残るので、縁がぎざぎざになります。
`shape` で球を生成すれば、`layers` を 1 文字も書かずにここまで来ます。

`scale` は塊の大きさ（ブロック）。大きくすると滑らかで大きな塊になり、
**1 まで下げると `random()` と同じ均一な散らばりに戻ります**（格子の間隔が 1 ブロック = 補間が起きない）。
0 以下をリテラルで書くとロードエラー、式が実行時に 0 以下へ落ちた場合は 1 として扱います。

> [!WARNING]
> **`noise()` は一様分布ではありません。** 格子点の間を補間するので値が 0.5 付近に寄ります。
> `"chance": "noise(8)"` はおよそ半分のセルに置きますが、
> **`noise(8) < 0.2` は 20% ではなく数 % しか通りません。** 割合で狙うなら実機で見て調整してください。

> [!NOTE]
> **1 つの繋がった塊になる保証はありません。** 閾値で切った結果が 2 つに割れることも、
> 穴が空くこともあります。`noise()` が約束するのは「塊っぽく見える」までです。

> [!NOTE]
> **同じ実行の中では 1 つの繋がった場です。** 場はワールド座標の関数なので、アンカーが 2 箇所あっても
> 2 つの配置が**繋がって見えます**（`chance` の散らばりがアンカーごとに違うのとは別の話）。
> 次の実行では別の場になります。

> [!NOTE]
> **`cell_*` でできるのは「削る」方向だけです。** 描いていないセルは生えません。
> 削る対象を手で描かずに用意するのが次の節の `shape` です。

### 手で描かずに形を生成する

`layers` の代わりに `shape` を書くと、形を生成します。

```json
{
  "name": "vein",
  "shape": { "type": "sphere", "radius": 8, "symbol": "X" },
  "mappings": {
    "X": { "block": "minecraft:iron_ore",
           "chance": "1 - sqrt(cell_x^2 + cell_y^2 + cell_z^2) / 8" }
  }
}
```

半径 8 の球（**2109 セル**）を、17×17×17 = 4913 文字を書かずに出せます。
上の `chance` と組み合わせると、そのまま輪郭のぼけた鉱脈になります。

| キー | 型 | 説明 |
| :--- | :--- | :--- |
| `type` | String | 形の種類。今は `sphere` だけ |
| `radius` | 数値 | 半径。**式は書けません**（下記） |
| `symbol` | String | 全セルに入る 1 文字。`mappings` にエントリが必要 |

生成される球は `dx² + dy² + dz² <= radius²` の整数判定なので、**同じ半径なら必ず同じ形**です。
半径 0 は中心 1 セル、1 は 7 セル、2 は 33 セル、4 は 257 セル、8 は 2109 セル、16 は 17077 セル。

- **`layers` との併記はロードエラー**です（セルの中身を 2 通り指定したことになります）
- **アンカーは中心**です。`anchor` との併記はロードエラー — 全セルが同じ文字なので
  `anchor` に選べるものがありません
- **中身は詰まっています。** 中空にしたいなら `chance` で削ってください
  （`"chance": "sqrt(cell_x^2 + cell_y^2 + cell_z^2) > 7"` で殻だけになります）
- **1 パターン 20000 セルが上限**です。全セルを一度に書き込むので、それ以上は必ず引っかかります
  （半径 16 まで通り、17 は超えます）

> [!WARNING]
> **`radius` に式は書けません。** 形はファイルを読んだ時点で確定し、そこから先は機械の向きごとに
> キャッシュされます（`cellsFor` は向きしか受け取りません）。式を評価する場所がどこにもありません。
>
> Tier で大きさを変えたいなら、**大きいほうを生成して `chance` で削ってください** ——
> `"chance": "sqrt(cell_x^2 + cell_y^2 + cell_z^2) <= tier"` で、Tier が半径になります。

### アンカー

レシピは機械側の構造体の記号を名指しします。その記号として記録された各ブロックが候補になり、
**アンカーのセルがそのブロックに重なるように**パターンが置かれます。

パターンの中にアンカーを描けるので、3×3×3 の配置を台座の**中心に**合わせられます
（隅を基準にする必要がありません）。`anchor` も `Q` も書かなければ、パターンの最初のセルが
基準になります。

`anchor` に書いた文字が `layers` に無い場合、隅を基準に読み替えたりせず**エラーになります**。

### 向き

**パターンは自分の `defaultFacing` を持ちません。** 変換に使うのは**使われる側の機械の向き**なので、
機械と一緒に回り、機械に対してだけ回転することがありません。

裏を返すと、同じファイルでも縦置きの機械と横向きの機械では意味が変わります（縦置きでは層が行に
移ります）。**その機械の構造体を書くときと同じ向きで**書いてください。

### 機械の外へ伸ばす

パターンは形成判定が触るブロックに限定されません。機械の形の外に出るセルも普通に解決するので、
IO の領域を機械の横や下に置けます。

## 3. レシピからの参照

```json
{
  "inputs": [
    { "type": "structure", "pattern": "altar_core", "symbol": "P", "consume": true }
  ],
  "outputs": [
    { "type": "structure", "pattern": "altar_spent", "symbol": "P" }
  ]
}
```

| キー | 意味 |
| :--- | :--- |
| `pattern` | パターンの `name` |
| `symbol` | パターンの基準になるブロックの記号 |
| `amount` | 一致・書き込みを要求するアンカーの数。既定は 1。式が使える |
| `consume` | input のみ。一致した配置を丸ごと消す |
| `optional` | 一致しなくてもレシピを開始・完了できる |
| `index` | 指定した割り当て番号のポートだけを対象にする |
| `pertick` | 稼働中も検査 / 書き込みを繰り返す |

### 入力として

アンカーが 1 つと数えられるのは、**すべてのセルが一致したときだけ**です。部分一致は部分点に
なりません。そこが、ブロック入力を並べたものとの違いです。

`consume` は個数ではなく**配置全体**を消します。半分だけ残った配置は「小さい配置」ではなく
壊れた配置で、次の検査でも一致しません。

### 出力として

空気のセルも含めて**すべてのセルを書き込みます**。同じ仕組みで、配置を作ることも
（空気で描いて）消すこともできます。

**上書きします。** セルごとの「置けるときだけ」判定はありません。パターンは一体として置くもので、
埋まっているセルを飛ばすと、**レシピが約束した配置ではないもの**を機械が作ったことになります。
特定の地面の上でだけ動かしたいなら、前段に `structure` の入力を置いてください。

ただし**機械自身は上書きしません**。形成判定が記録したブロックに 1 セルでも重なるアンカーは
選ばれないので、端に寄ったアンカーからパターンが壁を突き抜けて、レシピを走らせている構造体を
置き換えてしまうことはありません。

容量チェックが見るのは**使えるアンカーが足りているか**です。出力の置き場が無いレシピは、
入力を消費して何も置かないのではなく、開始そのものを断ります。

### どこに置かれるかを決める

記号は普通**複数のブロックを指します**（床は同じ記号の繰り返し）。そして
**アンカーを選ぶのは出力側であって作者ではありません**。使えるアンカーが複数あるとき、
どれに書かれるかはレシピからは制御できません。

これを決めさせる手段が**パターンの footprint（占有範囲）**です。**アンカーが 1 つしか
成立しない広さで描いてください。** 部屋の幅いっぱいのパターンは、床の中心ブロックにしか
乗りません（他のアンカーでは壁に食い込むため）。入力と出力を同じ footprint で描けば
必ず同じ場所を指すので、**「その配置をその場で変換する」が成立します**。

## 4. スキーマのバージョン管理

パターンのファイルは読み込み時に構造マイグレーション機構を通ります。後からフォーマットを変えても
既存のファイルを自動で直せます。変換されたファイルは書き戻され、元のファイルは `.bak` として残ります。

これがパターンをレシピ JSON に埋め込まず別ファイルにしている理由です。レシピ JSON には
スキーマの版管理が無いので、そこに書いたものは永久に固定されます。

## 5. コマンド

- `/okmodular reload`: 構造体・パターン・Tier・レシピを再読み込みします。レシピはパターンを
  名前で解決するので、**パターンのほうが先に**読み直されます。
