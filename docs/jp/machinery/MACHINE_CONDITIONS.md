# 機械の稼働条件

構造定義に条件を書くと、**その機械はレシピに関係なく、条件を満たさない間止まります**。
レッドストーン信号で止めるのと同じ位置にある仕組みです。

## 1. レシピの条件との違い

条件を書ける場所が 2 つあります。**別々に効きます。**

| 書く場所 | 効く範囲 |
|---|---|
| レシピの `conditions` | **そのレシピだけ**。条件を満たさないレシピは選ばれない |
| **構造の `conditions`** | **機械そのもの**。どのレシピを回そうとしていても止まる |

「この機械は雨の日しか動かない」は構造側、「このレシピは雨の日しか作れない」はレシピ側です。

## 2. 書き方

構造定義のトップレベルに書きます。

```json
{
  "name": "rain_collector",
  "conditions": [
    { "weather": "RAIN" }
  ],
  "layers": [ "..." ]
}
```

**1 つだけなら配列にしなくてよい**です。

```json
"conditions": { "weather": "RAIN" }
```

書ける条件は**レシピの `conditions` と同じもの**です（天候・バイオーム・ディメンション・
ブロック・式・論理演算子）。詳しくは [レシピの JSON フォーマット](../recipes/JSON_FORMAT.md) を見てください。

### 機械の状態も条件にできる

式を使うと、機械自身の状態を見られます。

```json
"conditions": [
  { "expression": "energy > 1000" }
]
```

使える名前は [式のリファレンス](../recipes/EXPRESSION_REFERENCE.md) にあります。

## 3. 条件を満たさないとどうなるか

**すべての条件を満たさないと、機械は 1 tick も進みません。** GUI には
`稼働条件を満たしていません: <条件>` と出ます。表示されるのは**最初に満たさなかった条件**です。

> [!IMPORTANT]
> **条件は「かつ」で結ばれます。** 1 つでも満たさなければ止まります。
> 「どれか 1 つでよい」なら `or` で明示的に囲んでください。
>
> ```json
> "conditions": [ { "or": [ { "weather": "RAIN" }, { "weather": "THUNDER" } ] } ]
> ```

## 4. 稼働中に条件が崩れたとき — `conditionPolicy`

レシピを回している途中で条件が崩れることがあります（雨が止んだ、電力が下がった）。
そのときどうするかを選べます。

| 値 | 挙動 |
|---|---|
| **`pause`（既定）** | その場で**凍結**して待つ。条件が戻れば**続きから**再開する。**消費済みの材料は失われない** |
| `abort` | レシピを**破棄**する。**消費済みの材料は戻らない** |

```json
{
  "conditions": [ { "weather": "RAIN" } ],
  "conditionPolicy": "abort"
}
```

`pause` が既定なのは、**レッドストーン停止と同じ挙動**で、かつ何も失わないからです。
`abort` は「条件が崩れたら生産が台無しになる」緊張感を作りたい機械のための選択肢です。

> [!WARNING]
> **`abort` は消費済みの材料を返しません。** これはこの mod で唯一、
> 材料を消費した可能性のあるレシピを破棄する経路です。
> プレイヤーが放置して使う機械には向きません。

## 5. 書かなければ何も変わらない

`conditions` も `conditionPolicy` も**任意**です。書いていない構造定義は、
この機能が入る前と**まったく同じ**に動きます。条件が無い機械は判定のための
オブジェクトを 1 つも作らないので、処理も増えません。

## 6. 注意点

### 綴りを間違えた条件は「無視」される

読めない条件は**読み込み時に警告を出して捨てられます**（ファイル名つき）。
つまり**門が閉まるのではなく緩みます** — 書いたつもりの条件より少ない条件で機械が動きえます。
`/ok multiblock reload` の後はログを確認してください。

方針名（`conditionPolicy`）の綴りを間違えた場合も、警告を出して**既定の `pause`** になります。

### 条件文の言語はサーバ側で決まる

GUI に出る条件の文は**サーバのロケール**で作られてからクライアントに送られます。
マルチプレイでは、クライアントの言語設定と一致しないことがあります。
既存の「出力容量が足りません」の表示と同じ仕組みです。
