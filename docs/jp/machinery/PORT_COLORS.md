# ポートの色分け

機械のポートを色で塗り分けると、**同じ色のポートだけが 1 つのまとまりとして扱われます**。
1 台の機械の中に、独立して材料を受け取る系統を複数作れます。

## 1. 何ができるか

アセンブリラインのように、**同じ機械で複数の系統を並べて管理**したいときに使います。

- 赤いポートに入れた材料は、赤いポートから出てくる
- 青いポートに入れた材料は、青いポートから出てくる
- 赤と青が混ざってレシピが成立してしまうことがない

> [!IMPORTANT]
> **同時に走るレシピは 1 つだけです。**
> 色分けは「どの材料をひとまとめに見るか」と「どの色から先に見るか」を決めるもので、
> **並列処理ではありません。** 赤と青の両方に材料が入っていても、機械は先に赤のレシピを回し、
> 終わってから青を回します。

## 2. 塗り方

| 操作 | 結果 |
|---|---|
| ポートを**染料で右クリック** | その色に塗る（染料を 1 個消費） |
| ポートを**スニーク + 染料で右クリック** | 色を落とす（染料は消費しない） |
| AE2 の **Color Applicator** | 塗る / 色を落とす |

染料を持っていないときの右クリックは今までどおり GUI が開きます。
既に同じ色のときは染料を消費しません。

> [!NOTE]
> **IC2 のペインターは未検証です。** 対応しているかどうかは確認できていません。

**外部ブロック（バニラのチェストなど）をポートとして使っている場合は、まだ塗れません。**
塗っていない扱いになるので、下の規則により全ての色から共有されます。

## 3. どのポートがどのまとまりに入るか

規則は 5 つです。

| # | 規則 |
|---|---|
| 1 | 塗ったポートは、**自分の色のまとまりにだけ**入る |
| 2 | **塗っていないポートは、すべてのまとまりに入る** |
| 3 | まとまりを見る順番は 白 → 橙 → 赤紫 → 空色 → 黄 → 黄緑 → 桃 → 灰 → 薄灰 → 青緑 → 紫 → 青 → 茶 → 緑 → 赤 → 黒 |
| 4 | **塗っていないポートだけのまとまりは最後**に見る |
| 5 | コントローラ自身は色に関係なくすべてのまとまりに入る |

### 規則 2 の意味 — 塗らないと共有される

エネルギーハッチを色ごとに用意しなくて済むようにするための規則です。

```
赤ポート: アイテム入力・アイテム出力
青ポート: アイテム入力・アイテム出力
無色:     エネルギー入力 1 個

→ 赤のまとまり = 赤の入力・赤の出力・無色のエネルギー
→ 青のまとまり = 青の入力・青の出力・無色のエネルギー
```

**代償があります。** 塗っていない入力ポートに入れた材料は、**どの色からも見えます**。
つまり色による隔離は完全ではありません。完全に分けたいなら**すべてのポートを塗ってください**。

### 規則 4 の意味

規則 2 の帰結です。「塗っていないポートだけのまとまり」は塗っていないポート全部を含むので、
ほぼ何にでもマッチします。先に見てしまうと色分けが意味を失います。

塗っていないポートが 1 つも無い機械では、このまとまりは作られません。

## 4. レシピの選ばれ方

まとまりを順番に見て、**最初に「レシピが成立して、かつ出力が入る」まとまり**を動かします。

> [!NOTE]
> **出力が塞がっているまとまりは飛ばして次を見ます。**
> 赤の出力タンクが満杯でも、青は動けます。

どのまとまりも動かせなかったときは、**優先度がいちばん高い色のエラー**が GUI に出ます。

## 5. 見え方

塗ったポートは、その色で表示されます。機械の構造そのものに色が設定されている場合よりも、
**ポートに塗った色が優先**されます。塗っていないポートの見た目は変わりません。

## 6. 保存

塗った色はワールドに保存され、再読み込み後も残ります。

順序つきポート位置（構造 JSON の `portIndex`）とは**別の軸**です。色で分けたまとまりの中で
番号が見られるので、両方を同時に使えます。
