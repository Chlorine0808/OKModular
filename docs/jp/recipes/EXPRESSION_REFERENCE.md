# 式パーサー 変数・関数リファレンス

OKModular の式パーサー（`ExpressionParser`）で使える変数と関数をまとめたリファレンスです。
式は、JSON レシピの `amount` フィールド、条件の `expression`、構造体の性能係数などに書けます。

## 関連ドキュメント

- [JSON フォーマット](./JSON_FORMAT.md) - 基本的な JSON 構文
- [条件 (Conditions)](./CONDITIONS.md) - `expression` 条件の書き方
- [デコレータ (Decorators)](./DECORATORS.md) - `chance` などに式を渡す
- [実用例集](./EXPRESSION_EXAMPLES.md) - 実践的なレシピ例

## 1. 基本演算

算術演算と論理演算が使えます。

- 算術演算: `+`, `-`, `*`, `/`, `%`（剰余）
- 累乗: `^` / `**`（どちらも同じ演算子で、`pow(a, b)` と書くのと同じ）
- 指数タワー: `^^`（`a ^^ 3` = `a ^ (a ^ a)`。`tetrate(a, n)` と書くのと同じ）
- 比較演算: `==`, `!=`, `>`, `<`, `>=`, `<=`
- 論理演算: `&&`（AND）, `||`（OR）, `!`（NOT）
- グループ化: `()`, `{}`

### 累乗の結合

累乗は右結合の演算子です。優先順位は `*` `/` より高く、単項マイナスより低くなっています。

| 式 | 読み方 | 値 |
| :--- | :--- | :--- |
| `2 * 3 ^ 2` | `2 * (3 ^ 2)` | 18 |
| `2 ^ 3 ^ 2` | `2 ^ (3 ^ 2)` | 512 |
| `-2 ^ 2` | `-(2 ^ 2)` | -4 |
| `2 ^ -1` | 指数に符号を書ける | 0.5 |

`^^` の優先順位と結合の向きも、累乗と同じです。

> [!WARNING]
> **`^^` を使える範囲は極端に限られます。** double に収まるのは底が 2 なら 4 段までで、
> `2 ^^ 5`（= 2 の 65536 乗）は Infinity になります。`3 ^^ 4` と `10 ^^ 3` も Infinity になります。
> この狭さは記法の性質によるもので、実装の制限ではありません。
>
> 段数は 64 段で打ち切ります。この打ち切りは大きな数を止めるためではなく、**終わらない式を止めるため**にあります。
> 底が e^(1/e) ≈ 1.4447 より大きければ、値は数段で Infinity に達するので、計算は自然に止まります。
> 一方、底がそれ以下だと値は収束します（`1.4 ^^ n` は 1.887 付近、`1 ^^ n` はいつまでも 1）。
> この場合は、値を見ても計算をいつ止めればよいか分かりません。
> そのため、危ないのは `"2 ^^ 1000000000"` ではなく `"1.4 ^^ 1000000000"` のほうです。

> [!TIP]
> 条件式（`1 == 1`）は、数値計算の中では `1`（真）または `0`（偽）として扱われます。
> 例: `10 + (day > 100) * 5`（経過日数が 100 を超えていれば 15、そうでなければ 10）

## 2. 組み込み変数

### ワールド変数
機械が置かれている世界の情報を読みます。

#### 時間・暦
- `day` / `total_days`: 累積経過日数
- `time`: 現在の時刻（0 - 23999）
- `tick`: ワールドの総経過時間（Total World Time の生の tick 値）
- `moon` / `moon_phase`: 現在の月齢（0 - 7、0 = 満月、4 = 新月）

#### 座標・ディメンション
- `x` / `y` / `z`: 式を評価している位置の座標。通常はコントローラの位置ですが、
  `offset` 条件の中ではずらした先を、[構造 IO パターン](../structures/STRUCTURE_IO.md)の
  `mappings` の中ではそのセルを指します
- `cell_x` / `cell_y` / `cell_z`: アンカーからそのセルまでのずれ。軸はパターンの軸で、機械の向きと一緒に回ります。
  `cell_y` は書いた層より上が正です。パターンの `mappings` の中だけで意味を持ち、それ以外の場所では 0 を返します
- `dimension`: 現在のディメンション ID（オーバーワールド=0、ネザー=-1、エンド=1）

#### 天候・環境
- `is_day`: 昼であるか（1 か 0）
- `is_night`: 夜であるか（1 か 0）
- `is_raining`: 雨が降っているか（1 か 0）
- `is_thundering`: 雷雨であるか（1 か 0）
- `temp`: コントローラ位置のバイオーム温度（0.0 〜 2.0）
- `humidity`: コントローラ位置のバイオーム湿度（0.0 〜 1.0）

#### 光・空間
- `light`: コントローラ位置の明るさ（0 - 15。空の光とブロック光源の光を合わせた値）
- `light_block`: ブロック光源だけの明るさ（0 - 15）
- `light_sky`: 空の光だけの明るさ（0 - 15）
- `can_see_sky`: コントローラから空が見えるか（1 か 0）
- `can_see_void`: コントローラの真下が Y=0 まで空洞か（1 か 0）

#### レシピ進行
- `recipe_tick`: 現在のレシピが開始してからの経過時間（tick）
- `progress_tick`: 現在のレシピの進捗の生の tick 値

#### その他
- `redstone_signal`: コントローラが受けているレッドストーン信号強度（0 - 15）
  - `redstone` という名前は、将来のレッドストーンポート用に予約してあるため使えません
- `random_seed`: レシピ評価セッションのシード値（`random()` / `chance()` の再現性に使う）
- `world_seed`: ワールドのシード値
- `facing`: 機械の向き（0:下, 1:上, 2:北, 3:南, 4:西, 5:東）

### 定数
- `pi`: 円周率（π ≒ 3.14159）
- `e`: ネイピア数（e ≒ 2.71828）

## 3. 機械のプロパティ

機械の現在の状態を読みます。

### 資源プロパティは全資源種で同じ形

7 つの資源種は、すべて同じ接尾辞を持ちます。以下の `K` を資源種の名前に読み替えてください。

`K` = `item` / `fluid` / `gas` / `energy` / `mana` / `essentia` / `vis`

| 書き方 | 意味 |
|---|---|
| `K` / `K_stored` / `K_total` / `total_K` | 現在の保持量 |
| `K_max` / `K_capacity` / `total_K_max` / `total_K_capacity` | 容量 |
| `K_f` / `K_free` / `K_space` | 空き |
| `K_p` / `K_percent` | 充填率（0.0 〜 1.0） |

たとえば `gas_stored` `total_vis` `essentia_percent` のような形になります。

搬入側と搬出側で格納が分かれる資源種（`item` / `fluid` / `gas`）は、さらに方向つきの名前を持ちます。

| 書き方 | 意味 |
|---|---|
| `K_in` / `K_out` | 搬入側 / 搬出側の量 |
| `K_f_in` / `K_f_out` | 搬入側 / 搬出側の空き |

`energy` / `mana` / `essentia` / `vis` は単一のプールなので、方向つきの名前はありません
（方向を指定しても選ぶものがなく、答えは合計と同じになるため）。

### 種類を指定する関数

その資源種の合計ではなく、特定の流体・ガス・アスペクト・アイテムの量を知りたい場合は、同じ名前に引数を 1 つ渡します。
引数は必ず 1 つで、それより多くても少なくてもエラーになります。

```
fluid("water")        item("minecraft:stone")     essentia("ignis")
fluid_in("water")     item_out("minecraft:iron_ingot")
fluid_f_out("lava")   item_f_in("minecraft:coal")
```

どの形が引数を取れるかは、資源種によって違います。種類を名指しできるのは、
その資源種が複数の種類を持つ場合だけです。

| 資源種 | 引数を取れる形 |
|---|---|
| `item` | `item` / `item_in` / `item_out` / `item_f` / `item_f_in` / `item_f_out` |
| `fluid` / `gas` | `K` / `K_in` / `K_out` / `K_f_in` / `K_f_out` |
| `essentia` / `vis` | `K` のみ |
| `energy` / `mana` | なし（単一の種類の単一プールなので、名指しする対象がない） |

### 補足

- エネルギー: `power` / `power_p` は `energy` / `energy_p` の別名です。
  `energy_per_tick` は 1 tick あたりのエネルギー消費量（稼働中の `perTick` 入力の合計）で、保持量ではないので上の表には含まれません。
- アイテム: 容量は「スロット数 × 64」で表します。
  ただし `item_f` は容量から引いた値ではなく、実際に入る個数です
  （スタック上限が種類ごとに違うため、引き算では実態と合いません）。
- アイテムのスロット情報: `item_slot()` は合計スロット数、`item_slot_in()` と `item_slot_out()` は方向ごとのスロット数、`item_slot_empty()` は空きスロット数です。

> [!NOTE]
> **方向を指定した空きは、共有容量からの引き算ではありません。**
> 液体とガスは搬入タンクと搬出タンクが別物なので、`fluid_f_in` は搬入タンクの空きだけを返します。
> 一方、`fluid_f`（方向なし）は「容量 - 保持量」です。

### 統計・状態
- `recipe_count` / `count_recipe`: 機械が処理したレシピの累計回数
- `recipe_types_count` / `count_recipe_type`: 処理したレシピの種類の数
- `progress` / `progress_percent`: 現在のレシピの進行度（0.0 ~ 1.0）
- `tier`: 機械の現在の Tier（完成時の払い出しでは開始時の Tier。[5. 評価タイミング](#5-式が書けるフィールドと評価タイミング)を参照）
- `is_running`: 機械が動作中であるか（1 か 0）
- `is_waiting`: 出力先が埋まっていて待たされているか（1 か 0）
- `timeplaced`: 機械が設置されてからの累積時間（tick）
- `timecontinue`: 機械が連続稼働している時間（tick）

### 構造プロパティ
構造体の定義が決める性能係数です。

- `batch`: 現在のバッチサイズ
- `speed_multi`: 速度倍率
- `energy_multi`: エネルギー倍率

> [!NOTE]
> **バッチサイズは量に自動で掛かります。** `"amount": "2 + tier"` のように式で書いた量も、バッチ 3 で稼働すれば 3 倍になります。
> そのため式の中で `batch` を掛ける必要はなく、掛けると二重に掛かります。
> `batch` 変数は、バッチサイズそのものを条件に使いたい場合のためのものです。
>
> 完成時の出力に `random()` を書いた場合は、バッチの回数だけ乱数を引いて合計します。
> `"1 + floor(random() * 3)"` をバッチ 3 で回すと、結果は 3〜9 の連続値になります
> （1 回引いて 3 倍する方式だと 3 / 6 / 9 しか出ません）。バッチ n は、n 回実行したのと同じ扱いです。
>
> `bonus` / `weighted_random` デコレータも同じ扱いで、バッチ 3 なら 3 回判定します。
> 詳細は [デコレータ](./DECORATORS.md#バッチとの関係) を参照してください。

## 4. 関数リファレンス

### 数学関数
- `abs(x)`, `sqrt(x)`, `cbrt(x)`, `pow(base, exp)`
- `min(a, b...)`, `max(a, b...)`
- `sin(x)`, `cos(x)`, `tan(x)`（入力はラジアン）
- `asin(x)`, `acos(x)`, `atan(x)`（出力はラジアン）
- `atan2(y, x)`: 象限を保った逆正接
- `rad(deg)`, `deg(rad)`（度とラジアンの変換）
- `floor(x)`, `ceil(x)` / `ceiling(x)`, `round(x)`
- `clamp(val, min, max)`
- `sign(x)`: 符号（-1 / 0 / 1）
- `exp(x)`, `log(x)` / `ln(x)`（自然対数）, `log10(x)`
- `log(x, base)`: 任意の底の対数（`log(8, 2)` = 3）。`x <= 0`、`base <= 0`、`base == 1` のときは **0** を返します
- `fact(n)`: 階乗
- `fact(n, k)`: k 重階乗。`n(n-k)(n-2k)…` を、項が正である限り掛ける（`fact(10, 2)` = 10·8·6·4·2 = 3840）
- `tetrate(a, n)`: `a` を `n` 段積んだ冪（`a ^^ n` と同じ）
- `perm(n, r)` / `npr(n, r)` / `permu(n, r)` / `permutation(n, r)`: 順列
- `combi(n, r)` / `ncr(n, r)` / `combination(n, r)`: 組み合わせ

> [!NOTE]
> `log(x)` は `ln` と同じ自然対数です。常用対数には `log10(x)` を使います。
> `log` / `ln` / `log10` は、`x <= 0` のとき例外を投げずに **0** を返します。

### 乱数

- `random()`: 0 以上 1 未満の乱数。隣り合う座標どうしでも無関係な値になる（塩胡椒状）
- `noise(scale)`: 0 以上 1 未満の値をとる場で、近い座標どうしは近い値になる。`scale` は塊の大きさ（ブロック単位）。
  塊で湧かせたいときはこちらを使う。ただし一様分布ではない（値は 0.5 付近に寄る）
- `chance(x)`: 確率 `x`（0.0 - 1.0）で 1、それ以外で 0 を返す

> [!IMPORTANT]
> **`random()` と `chance()` は、引くたびに値が変わる乱数ではありません。** 値は機械の評価シード（`random_seed`）から計算するので、
> 1 回の実行の中では何度評価しても同じ値を返します。この値はセーブ・ロードをまたいでも変わらず、実行が変われば別の値になります。
>
> たとえば `"1 + floor(random() * 3)"` を毎 tick 評価しても、値は変わりません。
> tick ごとに値を変えたいなら、`progress_tick` や `tick` を式に混ぜてください。
>
> 例外は 2 つあり、どちらも 1 回の実行の中で n 回引きたい場合のためのものです。
> バッチ（[3. 機械のプロパティ](#3-機械のプロパティ)末尾の NOTE）と、位置ごとに引くデコレータ
> （[デコレータ](./DECORATORS.md#3-抽選の仕組み)）は、シードをずらして引き直します。

### 周囲を調べる関数

- `can_see_sky(filter...)`: 上空が見えるかを判定する。ガラスなどを透過させるには ID を指定する
- `can_see_void(filter...)`: 真下が奈落かを判定する
- `count_blocks(distance, filter...)`: 周囲にある特定のブロックを数える
    - 例: `count_blocks(1, "minecraft:iron_block")`

> [!NOTE]
> `can_see_sky` と `can_see_void` は、括弧を省いて `can_see_sky == 1` のように変数としても書けます。
> 変数形式は透過させるブロックを指定できない素の判定なので、透過の指定が要るときだけ関数形式にします。
> **どちらもコントローラの 1 つ上（`can_see_void` は 1 つ下）から数えます。**
> コントローラ自身は不透過キューブなので、自分の座標を含めると答えが必ず false になるためです。

### NBT へのアクセス

- `nbt('key')`: 機械本体の NBT を読む
- `nbt('symbol', 'key')`: 構造体の特定シンボル位置の NBT を読む
- `has_nbt('key')` / `has_nbt('symbol', 'key')`: NBT キーが存在するか

NBT はすべて `nbt(...)` で読み書きします。
対象は常に引数で指定し、階層パスは引数の文字列の中にドットで区切って書きます。

```
nbt('energy')                機械自身のトップレベルキー
nbt('display.Name')          機械自身の階層パス
nbt('S', 'stored_energy')    シンボル S の位置の TileEntity
nbt('S', 'a.b.c')            シンボル S の階層パス
```

#### 書き込み（代入）

`nbt(...)` を代入の左辺に置きます。途中の compound は自動で作られます。

```json
"nbt": "nbt('customData.level') = 7"
"nbt": "nbt('temperature') += 50"
"nbt": "nbt('display.Name') = 'Excalibur'"
```

- 演算子は `=` `+=` `-=` `*=` `/=`
- **シンボル経由の代入はできません**（`nbt('S', 'x') = 1` はエラー）。書き込み先は
  その式を書いたフィールドが持つ NBT（出力アイテムや設置するブロック）で、
  シンボルは読む対象を指すものだからです

#### 型サフィックス

数値に付けると NBT のタグ型を固定できます。付けない場合は double です。

| サフィックス | 型 | 例 |
|---|---|---|
| `b` / `B` | byte | `127b` |
| `s` / `S` | short | `32767s` |
| `i` / `I` | int | `2147483647i` |
| `L` | long | `9223372036854775807L` |
| `f` / `F` | float | `3.14159f` |
| `d` / `D` | double | `2.718281828d` |

long のサフィックスは大文字だけです（小文字の `l` は `1` と紛らわしいため）。

## 5. 式が書けるフィールドと評価タイミング

| フィールド | 評価タイミング |
|-----------|--------------|
| `duration` | レシピ開始時（ただし構造体で `"durationPolicy": "perTick"` を指定すると実行中毎 tick） |
| 入力の `amount` | 消費時（`perTick` なら毎 tick、そうでなければレシピ開始時） |
| 完成時に出す出力の `amount` | **レシピ開始時**。下の NOTE を参照 |
| `perTick` 出力の `amount` | 毎 tick |
| `energy` / `mana` などのリソース量 | 上と同じ（入力か出力か、`perTick` かで決まる） |
| 出力アイテムの `nbt` 式 | 出力時。性能は開始時の値（下の NOTE を参照） |
| レシピの `chance` デコレータ | レシピ 1 回につき 1 回だけ（完成時に判定）。性能は開始時の値 |
| 出力デコレータの `chance` | 判定時。性能は開始時の値 |
| `condition` / `conditions` | レシピ開始時と、稼働中は毎 tick |
| 構造体の `speedMultiplier` | 稼働中は毎 tick |
| 構造体の `batchMin` / `batchMax` | レシピ開始時 |
| 構造体の `energyMultiplier` | レシピ側が `energy_multi` を読んだとき |

> [!NOTE]
> **完成時の払い出しは、レシピを始めたときの機械の性能で決まります。**
> ここでいう性能は、`tier`・`tier.<部品>`・`speed_multi`・`energy_multi` の 4 つです。
> 稼働中に構造体を組み替えて Tier を上げても、そのレシピは始めたときの Tier で払い出します。
> 入力は開始時に消費されているので、完成時の性能を読むと、低 Tier で始めて高 Tier で終わらせる使い方が成立してしまいます。
>
> この規則は、完成時に評価する式のすべてに当てはまります。出力の量と `nbt` 式、レシピの `chance`、
> デコレータ（`bonus` の `chance` と出力、`random_block_output` の `count` など）が含まれます。
> セーブして入り直しても、開始時の性能は保たれます。
>
> 残量（`energy`・`energy_p` など）は開始時の値を写さず、読んだ時点の値を使います。
> `perTick` の資源・`condition`・構造体の `speedMultiplier` は毎 tick 評価するもので、この規則の対象外です。

構造体の性能係数の式からも、レシピと同じように機械のプロパティを読めます。
そのため `"speedMultiplier": "1 + tier * 0.25"` のように書けます。ただし、その係数自身の値は読めません。
詳しくは [構造体の JSON フォーマット](../structures/JSON_FORMAT.md) を参照してください。

## 6. 構造化形式（文字列の代わりにオブジェクトで書く）

式は文字列（`"tier * 2"`）のほかに、オブジェクトでも書けます。
書ける場所と意味は、文字列で書いた場合と同じです。

```json
"amount": { "type": "arithmetic", "operation": "*",
            "left":  { "type": "machine_property", "property": "tier" },
            "right": { "type": "constant", "value": 2 } }
```

上の例は `"amount": "tier * 2"` と同じ意味です。**普通は文字列で書いてください。**
文字列のほうが短く読みやすく、同じものを 2 通りで書く必要もありません。
オブジェクト形式は、式をプログラムで組み立てる場合や、文字列に収まらない指定をする場合のためのものです。

| `type` | 必須キー | 意味 |
|---|---|---|
| `constant` | `value`（数値） | 定数 |
| `string_literal` | `value`（文字列） | 文字列。`item('...')` のような関数に渡す値 |
| `machine_property` | `property` | 機械のプロパティ 1 つ（`tier` / `energy` など） |
| `world_property` | `property` | 世界のプロパティ 1 つ（`tick` / `moon_phase` など） |
| `component_tier` | `component` | 部品の Tier（`"glass"` など） |
| `arithmetic` | `operation` `left` `right` | 四則演算。`left` / `right` も式 |
| `map_range` | `input` `minIn` `maxIn` `minOut` `maxOut`（任意で `clamp`） | 値の範囲を別の範囲に写す |
| `nbt` | `key`（任意で `default` `symbol`） | NBT の値。`default` は読めなかったときの値 |
| `nbt_assignment` | `key` `value`（任意で `op`） | NBT へ書き込む。下記 |

### `map_range` で範囲を写す

```json
{ "type": "map_range", "input": { "type": "machine_property", "property": "energy_p" },
  "minIn": 0, "maxIn": 1, "minOut": 100, "maxOut": 20, "clamp": true }
```

`minIn`〜`maxIn` を `minOut`〜`maxOut` に線形に写します。上の例は
充填率 0% で 100、100% で 20 になるので、溜まっているほど速くなる書き方です。

`minOut` > `maxOut` のように、逆向きにも書けます。`clamp`（既定 `false`）を `true` にすると、
入力が範囲外でも出力は `minOut`〜`maxOut` の範囲に収まります。

### `nbt_assignment` の `op`

NBT に書き込むときの演算子です。既定は `"="` です。

```json
{ "type": "nbt_assignment", "key": "stored_power", "op": "+=",
  "value": { "type": "constant", "value": 1000 } }
```

文字列形式の `nbt('stored_power') += 1000` と同じです。

## 7. 注意点

### よくある間違い
- 文字列の引用符: 式は JSON の中で、`"amount": "tier * 2"` のように文字列として書きます。
- 大文字・小文字: 変数名はすべて小文字です（`Tier` ではなく `tier`）。
- 全角文字: 演算子や変数名に全角文字を使わないでください。
- ゼロ除算: 充填率や残量で割る式は、空のときに 0 除算になります。
  `energy_p > 0 ? floor(1000 / energy_p) : 0` のように分母を先に確認してください。
- `duration` に `speed_multi` を書く: 速度倍率はエンジンが毎 tick 適用しているので、**式に書くと 2 回掛かります**。
  `duration` は時間ではなく作業量です。エネルギーは逆で、`energy` に `energy_multi` を書くのが正しい使い方です。

式のパースに失敗したときのエラーは `logs/latest.log` に出ます。

### NEI での見え方

NEI は機械を持たないので、`tier` や `speed_multi` のような機械に依存する変数を評価できません。
`duration` が機械に依存する式である場合、NEI は秒数の代わりに式そのものを表示します。
定数だけで書かれた式（`floor(200 / 2)` など）は読み込み時に数値へ畳まれるので、秒数が出ます。

### パフォーマンス
式は毎 tick 評価されることがあるため、極端に複雑な式や、広範囲の `count_blocks` などの多用は避けてください。
